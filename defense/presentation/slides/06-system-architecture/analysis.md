# 06 · system-architecture — как и почему

## Зачем этот слайд
Сквозная схема «вход → предобработка → модель → вывод» (Дауренбаева сл. 10, Тоқтарова сл. 9–12). Задача 2 (гл. 2).

## Решения
- Диаграмма архива сохранена (`img/a07_1.png`); таблица исправлена:
  - **параметры моделей**: 23,5 / 10,7 млн по `results/tables/computational_and_iq.md` (A7), а не 25,6 / 12,2 млн — эти числа
    из демо (`data.js`), и сам `results/` помечает их как неверные;
  - «shared weights», «f ∈ ℝᵈ», «BGR uint8» убраны — детали реализации, не нужные совету;
  - правило агрегации «max(ŷ_L, ŷ_R)» заменено нейтральным «объединяются»: в гл. 4.2 диссертации правило не названо.
- Термины kk — по диссертации: «алдын ала өңдеу», «көру алаңының маскасы» (в архиве «препроцессинг», «FOV mask»).
- Архивная речь про «жеке шығарылған shared weights» заменена описанием потока данных.

- **Математическая постановка (2026-09-28, указание докторанта).** Слайд «Математическая постановка» есть у 7 из 15 защит
  (Алпар, Бакирова, Әйтім, Мерембаев, Муханов, Олжаев, Тоқтарова); отдельный слайд не заводится — постановка добавлена сюда,
  заголовок «Математическая постановка и архитектура модели». Четыре строки: 𝒫 как композиция T₇∘…∘T₀; решающее правило;
  обучение θ на выходе 𝒫 (focal loss, γ = 2) — формальная запись тезиса «𝒫 — часть модели»; ALO = |A ∩ L| / |L|
  (`thesis/governance/HYPOTHESIS.md` H-5: ALO = area(GradCAM ∩ lesion_mask) / area(lesion_mask)). Речь +1 фраза, 35 → 45 с.
