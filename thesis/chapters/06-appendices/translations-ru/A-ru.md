## ЧАСТЬ 1: ТЕКСТ РАЗДЕЛА

Раздел 3.1 взял на себя задачу воспроизвести код предобработки и обучения здесь, чтобы преобразование, применяемое к каждому изображению, было восстанавливаемо как исходный код, а не описывалось только в прозе. Данное приложение выполняет это обязательство. Его включение не является случайной документацией. В соответствии с центральной тезой настоящей работы, согласно которой модель представляет собой композицию предобработки и свёрточной нейронной сети, исходный код предобработки является частью спецификации модели. Его воспроизведение делает эту тезу проверяемой, а не просто утверждённой.

Код организован как пакет Python в `experiments/src/`. Стек предобработки находится в `experiments/src/preprocessing/`, публичный интерфейс которого экспортируется из `__init__.py`, а его оркестратор `PreprocessingPipeline` в `pipeline.py` связывает восемь этапов в порядке, указанном в главе 2.

Остальные компоненты распределены по соседним подпакетам. `data/` содержит загрузчики наборов данных, стратификатор на уровне пациента, унифицированную аугментацию и гармонизацию меток; `models/` – два фабрика базовых архитектур и утилиту двухэтапного дообучения; `training/` – цикл обучения, взвешенный focal loss и управление контрольными точками.

`evaluation/` содержит метрики, калибровку и статистические тесты, `explainability/` – карты внимания и рендеринг наложений, `experiments/` – драйверы экспериментов, а `utils/` – обработку конфигурации, утилиту зернирования для воспроизводимости и метрики качества изображения. Нижеприведённый каталог ограничен пакетом предобработки; более широкое дерево упоминается только для того, чтобы воспроизведение было полностью локализуемо.

Таблица A.1 сопоставляет каждый этап конвейера из главы 2 с модулем, который его реализует. Все пути указаны относительно корня репозитория и соответствуют файлам, присутствующим в версионируемом дереве исходного кода.

| Этап | Описание (глава 2) | Реализующий модуль |
|-------|--------------------|---------------------|

Этап 5 реализован более чем одним модулем, поскольку в конвейер включён полярный вариант CLAHE с двойным ограничением в качестве текущего значения по умолчанию (`polar_clahe.py`) наряду с прямоугольной плиточной формулировкой (`upgraded_clahe.py`); оба присутствуют в версионируемом исходном коде и воспроизведены в соответствии с каталогом. Этапы 0–5 и 7 применяются идентично при обучении и инференсе, за исключением того, что усиление контраста на этапе 5 является стохастическим во время обучения. Аугментация этапа 6 применяется только при обучении и вставляется перед нормализацией этапа 7, чтобы работать с изображениями `uint8`. Базовая ветвь обходит этапы 0–6 в пользу растяжения-масштабирования до 512x512 с последующей общей нормализацией по трём каналам, выбираемой через пресет конфигурации, а не путём редактирования конвейера. Интегрированная ветвь выполняет все восемь этапов и выдаёт четыре канала: три цветовых канала и маску поля зрения.

Чтобы установить, что данный каталог воспроизводит реальный исходный код, а не его парафраз, модуль плоского поля этапа 4 воспроизведён дословно из `experiments/src/preprocessing/flat_field.py`:

```python
"""
Stage 4: Flat-Field Correction.

Reduces uneven illumination by subtracting a heavily blurred version of the
image and re-centering at 128:

 corrected = image − GaussianBlur(image, σ) + 128

A large σ captures only the low-frequency illumination gradient, so the
subtraction removes broad brightness variation while preserving local vessel
and lesion detail.

σ is computed adaptively as σ = 0.07 × FOV_diameter. Correction
is applied only inside the FOV mask (padding pixels are left at zero).

Input/output images are RGB uint8 NumPy arrays.
"""

from __future__ import annotations

import cv2
import numpy as np

def apply_flat_field(
 image: np.ndarray,
 sigma: float = 45.0,
 mask: np.ndarray | None = None,
) -> np.ndarray:
 """
 Apply flat-field correction to reduce uneven illumination.

 Algorithm::

 blur = GaussianBlur(image, σ)
 corrected = image − blur + 128

 When *mask* is provided, correction is applied only inside the mask
 (``mask > 0``). Padding areas (``mask == 0``) are left at zero.

 Kernel size is derived automatically from *sigma* (passed as ``(0, 0)``
 to:func:`cv2.GaussianBlur`).

 Args:
 image: RGB uint8 NumPy array of shape ``(H, W, 3)``.
 sigma: Gaussian blur σ controlling the spatial scale of the
 illumination estimate.
 mask: Optional binary mask of shape ``(H, W)`` (float32 or uint8).
 When provided, only pixels where ``mask > 0`` are corrected;
 padding regions remain zero.

 Returns:
 Corrected RGB uint8 NumPy array of shape ``(H, W, 3)``.
 """
 blur = cv2.GaussianBlur(image, (0, 0), sigma)
 corrected = image.astype(np.float32) - blur.astype(np.float32) + 128.0
 corrected = np.clip(corrected, 0, 255).astype(np.uint8)
 if mask is not None:
 mask_3ch = np.expand_dims(mask > 0, axis=-1).astype(np.uint8)
 corrected = corrected * mask_3ch # zero out padding
 return corrected
```

Остальные модули следуют тем же соглашениям: сигнатуры с аннотациями типов, строки документации `Args`/`Returns`, пути, разрешаемые из конфигурации, а не захардкоженные, и использование `pathlib.Path` на протяжении всего кода. Они воспроизведены полностью из того же пакета.

Происхождение конвейера восходит к предшествующей опубликованной работе соискателя по усилению контраста и интеграции предобработки с классификацией, которая цитируется в тексте как предшествующая собственная работа. Источник, воспроизведённый здесь, объединяет эту линию в единую версионированную восьмиступенчатую систему, специфицированную в главе 2.

Источник воспроизводим на эквивалентном оборудовании, однако характеристики вычислительной эффективности, которые он демонстрирует, остаются специфичными для задокументированной конфигурации, и воспроизведение не предполагает утверждений о качестве, точности или готовности к развёртыванию. При условии, что источник каталогизирован и один модуль показан как реальная реализация на диске, цикл воспроизводимости, открытый в разделе 3.1, замыкается: фиксированная конфигурация таблицы 3.2, задокументированное оборудование и данный версионированный код совместно делают экспериментальный конвейер восстанавливаемым.
