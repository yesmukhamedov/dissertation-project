## 4.2 Preprocessing and Inference Services

The preprocessing module executes the eight stages defined in Chapter 2. Its significance for the system lies in the fact that this is the exact code path used by the experiments, not a re-run created for demonstration. Therefore, what the operator sees applied to a submitted image is the same processing applied to the corpora.

This identity is not for convenience. If the deployed pipeline were a separate execution, every result in Chapter 3 would describe a transformation different from what the system performs. The provision that preprocessing is a model component would then relate to the experiment, not the system. Maintaining a single execution is what makes the two one entity.

The module is configured in the sense required by the project: stages can be disabled and parameters changed. Ablation and parameter sweeps did exactly this. In the deployed configuration, parameters are those selected by the sweeps. The transformation is deterministic because all stochastic elements are limited to training.

The visualisation endpoint exposes the intermediate state after each stage, as well as the input channels the classifier ultimately receives. This is rare for a screening tool that requires stating a reason. Since this work views preprocessing not as preparation but as part of the model, a system showing only the final grade would have hidden half of the model.

Exposing the stages makes the transformation verifiable for a clinician who must assess the output cost. It also allows the provision of Chapter 2 to be checked against a working system, not just text. The operator can see illumination correction and contrast enhancement applied to their own image.

The inference module loads the trained checkpoint and provides a five-class grade. The prediction is organised at the patient level, not the image level. The interface accepts images of both eyes and returns a result per patient. The referable determination is accepted at this unit.

This choice follows from the partition order of the experiments. There, corpora were split at the patient level because patient images were correlated. A system grading images independently would offer the clinician two results without a rule for merging them.

Model selection is a configuration decision, not a runtime one. One checkpoint is held in memory at a time. This limits memory footprint to a single model and is one reason the service operates within a simple budget.

One discrepancy is registered here rather than left to be found later. The checkpoint served by the demonstrator is not the checkpoint that produced the results in Chapter 3. It is an earlier artefact from a superseded configuration. The figures the client displays beside it come from that earlier run.

The consequences are precise and limited. Nothing the demonstrator displays sources any number in this dissertation. The results of Chapter 3 come from the experimental record and nowhere else. The demonstrator shows what the system does. It is not evidence of how well it does it, and the two must not be confused.

The explanation module computes attention maps on request, following the formalism of Chapter 2, in the final convolutional block. A second discrepancy is placed beside the first. Maps are computed directly for images uploaded by the operator. The built-in walk-through cases, designed to show the system without patient data, provide stored proxy heat maps, not computed ones.

Any individual evaluating the system must know which of the two they are observing, and this distinction is recorded for that reason. It is unrelated to anything in Chapter 3: there, all attention metrics were computed against annotated masks in experimental models, not in this system.

The self-test module runs on startup and verifies that the deployed pipeline reproduces expected outputs on fixed inputs. Its function is to make silent divergence audible: a preprocessing stage that begins to behave differently after a dependency change would otherwise degrade results without any signal, whereas the test is cheap compared to that risk.

The error path handles inputs that fall outside the contract established in Chapter 2 and applies the acceptance protocol defined there. Corrupted containers are not accepted, images in which no coherent field of view can be recovered are withheld rather than passed to stages that would operate on meaningless content, and a low-confidence lateralisation is not confirmed but recorded as is.

Thus, the system does not fail silently on out-of-contract inputs; it fails visibly. This is the behaviour named in the initial design and realised here. The protocol does not generalise: it was designed against the clinical images used in this work and validated only for them.
