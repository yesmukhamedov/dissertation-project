## 4.2 Preprocessing and Inference Services

The preprocessing engine performs the eight stages defined in Chapter 2. Its significance for the framework lies in the fact that it is the same code path used in the experiments, rather than a re-implementation for demonstration purposes. Consequently, what the operator sees applied to the uploaded image is exactly what was applied to the corpora.

This identity is not merely a convenience. If the deployed pipeline were a separate implementation, every result in Chapter 3 would describe a transformation different from the one performed by the framework. In that case, the claim that preprocessing is a component of the model would apply to the experiment but not to the framework. Maintaining a single implementation makes these two objects identical.

The engine is configurable in the sense required by the project: stages can be disabled, and their parameters modified. This is precisely what the ablation and parametric sweeps did. In the deployed configuration, the parameters are those selected by the sweeps, and the transformation is deterministic, as the only stochastic elements are confined to training.

The visualisation point reveals the intermediate state after each stage, as well as the input channels that the classifier ultimately receives. This is sufficiently unusual for a screening tool to warrant an explanation of the reason. Since this work treats preprocessing as part of the model rather than as preparation, a framework showing only the final grade would conceal half of what the model is.

Exposing the stages makes the transformation verifiable for the clinician who must assess the output, and allows the claim in Chapter 2 to be checked not only by text but also by the working framework. The operator can see the illumination correction and contrast enhancement applied to their own image.

The inference module loads a trained checkpoint and outputs a five-class grading. The prediction is organised at the patient level, not the image level: the interface accepts images of both eyes and returns a result for the patient, which is the unit relative to which the referral decision is made.

This choice follows from the discipline of experimental splitting, where corpora were divided at the patient level precisely because patient images are correlated. A framework grading images independently would present the clinician with two results and provide no rule for combining them.

Model selection is a configuration decision, not a runtime decision. Only one checkpoint is held in memory simultaneously, which limits memory consumption to a single model and is one of the reasons the service operates within a modest budget.

One deviation must be recorded here, rather than left for subsequent discovery. The checkpoint serving the demonstrator is not the one that produced the results in Chapter 3. It is an earlier artefact, retained from a superseded configuration, and the metrics displayed by the client alongside it originate from that early run.

The consequence is precisely defined and bounded. Nothing displayed by the demonstrator is the source of any number in this dissertation, and the results in Chapter 3 derive from the experimental record and nowhere else. The demonstrator shows what the framework does; it is not evidence of how well it does so, and these two aspects should not be conflated.

The explanation module computes attention maps on demand, using the formalism from Chapter 2 on the final convolutional block. A second deviation stands alongside the first. Maps are computed in real time for images uploaded by the operator; embedded demonstration cases, which exist to allow the system to be shown without patient data, provide stored proxy heatmaps rather than computed ones.

Anyone evaluating the system must know which of the two variants they are examining, and this distinction is recorded here precisely for that reason. It has no bearing on the content of Chapter 3, where all attention measures were computed on experimental models against annotated masks, not within this system.

The self-check module launches at startup and verifies that the deployed pipeline reproduces expected outputs on fixed inputs. Its function is to make silent divergence visible: a preprocessing stage that begins to behave differently after a dependency change would otherwise degrade results without any signal, whereas the check is cheap compared to that risk.

The error-handling path processes inputs that fall outside the contract established in Chapter 2, applying the ingestion protocol specified there. Corrupted containers are rejected, images for which the field of view cannot be restored are held rather than passed to stages operating on meaningless content, and low-confidence laterality determinations are logged as such rather than asserted.

Thus, the system fails explicitly rather than implicitly when encountering out-of-contract input, which is the behaviour named in the original project and implemented here. What the protocol does not do is generalise: it is designed and validated only for the clinical images used in this work.
